# Поведение и границы проверки

Этот документ описывает код версии 1.1, а не результат независимого аудита.
Приложение и документация созданы с помощью ИИ. Замечания следует сверять с кодом.

## Данные и разрешения

- Вход: URL, переданный macOS, либо путь локального документа.
- Маршрутизатор не читает содержимое документа: передаёт его URL в Safari.
- Ссылки и пароль встречи существуют в памяти процесса; собственных журналов,
  базы данных, настроек с паролями или истории нет.
- NSWorkspace передаёт ссылку Zoom/Safari. Эти приложения, сама macOS и приложение,
  из которого пришла ссылка, имеют собственные механизмы хранения и журналирования.
- Собственных HTTP-запросов, аналитики, обновлений, фонового демона и login item нет.
- Приложение не использует shell для открытия URL и не получает root-права.
- После нажатия «Включить» запрашивает назначение обработчиком HTTP и HTTPS через
  NSWorkspace. Подтверждение контролирует macOS. Проверяет результат по обеим схемам.
- macOS может связать этот выбор с HTML-файлами. На проверенной macOS 26.6.2
  назначение Safari обработчиком всего типа HTML также меняло HTTP/HTTPS на Safari.
  Приложение передаёт локальный HTML в Safari; имя маршрутизатора в кнопке
  просмотра файла не требует отдельного исправления системных настроек.
- Системные настройки микрофона и камеры, Accessibility, Screen Recording,
  Full Disk Access и аккаунт Zoom приложению для его функций не нужны.
- Приложение не помещено в App Sandbox. Отсутствие вызовов в коде не означает
  принудительное ограничение прав будущих или изменённых сборок.

## Маршрутизация

Отдельный установщик описан ниже; этот раздел относится к приложению.

Проверяется точный хост `zoom.us` или окончание `.zoom.us`, а не вхождение подстроки.
Преобразование разрешено только для `/j/` с 9–11 ASCII-цифрами, без userinfo/port,
с параметрами `pwd`/`omn`, каждый не более одного раза. Исходное кодирование
параметров сохраняется. Неизвестные параметры не исполняются: исходный URL
открывается в Safari. Самостоятельный сетевой разбор коротких ссылок отсутствует.

`action=join` и `confno` задаёт приложение; значения входной ссылки не могут
заменить эти имена, поскольку такие query-параметры отправляются в Safari.
Fragment обычной Zoom-ссылки в deep link не переносится.

Zoom и Safari ищутся через NSWorkspace по bundle identifier (`us.zoom.xos`,
`com.apple.Safari`). Это использует реестр приложений macOS и не выполняет
самостоятельную проверку сертификата издателя найденного приложения.

## Ограничения и ошибки

- Открытие адреса в Safari не означает проверку безопасности сайта.
- Успех NSWorkspace означает передачу URL приложению, а не успешный вход в Zoom.
  Ошибка уже внутри Zoom не вызывает автоматический возврат в Safari.
- Камера/звук, аутентификация и зал ожидания зависят от Zoom.
- Назначение HTTP и HTTPS последовательное, не атомарное. Если второй шаг отменён
  или не удался, первый может сохраниться. Автоматического отката нет: повторите
  включение либо выберите прежний браузер в системных настройках.
- Старый браузер не запоминается. Отключение выполняется через настройки macOS.
- В unit-тестах нет AppKit-событий, диалогов, выбора системного браузера и Zoom.
- На Intel пройдены unit-тесты и нативная сборка в CI. GUI на Intel, старые macOS
  и установка скачанной сборки на другом Mac пока не проверены.
- Подпись ad hoc проверяет целостность относительно встроенной подписи, но не
  устанавливает личность автора. Developer ID и notarization в поставке отсутствуют.

## Установщик install.sh

Отдельный установщик обращается к GitHub Releases по HTTPS и скачивает один
закреплённый архив версии 1.1. SHA-256 задан в исходниках и проверяется **до**
распаковки; после неё проверяется локальная подпись приложения. Сам установщик
требует доверия к репозиторию/аккаунту публикации. Хеш не является независимым
подтверждением безопасности и не защищает от подмены скрипта у источника.

Скрипт работает без root/sudo, пишет во временную папку и папку установки,
не перезаписывает другую установленную сборку, отвергает симлинк по пути `.app`
и использует блокировку от одновременных запусков установщика. По умолчанию
открывает установленное приложение; `--no-open` отключает этот шаг. Системный
браузер меняется только после действий пользователя в приложении и диалогах macOS.
Установщик помечает новую копию атрибутом `com.apple.quarantine` для обычной
проверки первого запуска; не удаляет quarantine и не меняет настройки Gatekeeper.
Если первый запуск заблокирован, установка уже завершена, а разрешение запуска
пользователь даёт штатным способом через «Конфиденциальность и безопасность».

## Сообщения о проблемах

Передайте автору проблему с версией приложения, macOS и синтетическим примером URL.
Не прикладывайте реальные пароли встреч, токены регистрации, SSO или личные данные.
Если опубликован репозиторий, обычные ошибки можно описать в Issues. Детали
эксплуатируемой уязвимости сначала передайте владельцу проекта лично.

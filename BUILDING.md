# Сборка и проверка

## Требования и команды

Mac, macOS 12+, Apple Command Line Tools или Xcode со Swift.
Для установки инструментов Apple при их отсутствии: `xcode-select --install`.
Установку инструментов выполняет сам пользователь; скрипты сборки ничего не скачивают.

После чтения исходников и скриптов запустите в папке проекта:

```sh
zsh test.command
zsh build.command --universal
plutil -lint 'Zoom Link Router.app/Contents/Info.plist'
lipo -info 'Zoom Link Router.app/Contents/MacOS/ZoomLinkRouter'
codesign --verify --deep --strict --all-architectures 'Zoom Link Router.app'
```

`build.command` без `--universal` создаёт приложение только для архитектуры
текущего Mac. Сборка записывает `.app` рядом со скриптом и использует временный
каталог, который удаляется после выхода. Существующая `.app` в этой папке
пересобирается. Установленную копию в `/Applications` скрипт не меняет.
Скрипты сборки и тестов URL не назначают браузер и не запускают приложение или реальную встречу.

## Проверка установщика

`install.sh` не компилирует приложение: скачивает закреплённый архив релиза,
проверяет его и устанавливает готовую копию. По умолчанию открывает её для настройки.

```sh
bash -n install.sh scripts/test-installer.sh
bash scripts/test-installer.sh
```

Тесты скачивают архив для проверки, затем используют временные папки и подменяют
только загрузчик и команду открытия. SHA-256, распаковка, подпись, quarantine и
копирование проверяются настоящими системными инструментами. Проверяются успешная
установка, повторный запуск, сохранение другой копии, ошибки загрузки/хеша, симлинк,
блокировка и очистка временных файлов. Приложение и системные диалоги не запускаются.
Отдельно проверяется `--trust`: удаление quarantine у новой и существующей копии,
повторный запуск, сохранение чужого атрибута и отказ от снятия карантина при
неверной контрольной сумме. Всего 13 проверок установщика.
Для тестов без сети передайте путь к исходному `ZoomLinkRouter-1.1-handoff.zip`:
`bash scripts/test-installer.sh /absolute/path/ZoomLinkRouter-1.1-handoff.zip`.

`codesign --verify` проверяет целостность локальной подписи. Он **не** означает
проверку Apple, нотариальное заверение или независимый аудит безопасности.

## Что именно проверяется

`test.command` компилирует только `Router.swift` и тестовый `main.swift`.
Он не компилирует и не выполняет AppKit-код `source/main.swift`.
Проверяются преобразование URL, сохранение кодирования пароля, точное возвращение
исходного URL для Safari и неподходящие домены/пути/параметры.

Отдельная ручная проверка после сборки:

1. Запуск приложения, «Позже»: системный браузер не меняется.
2. «Включить», подтверждение macOS: назначены HTTP и HTTPS.
3. Обычная ссылка из внешнего приложения открывается в Safari.
4. Собственная тестовая встреча открывается в Zoom с ожидаемым паролем.
5. Сложная ссылка остаётся в Safari; локальный HTML/XHTML передаётся Safari.
6. Возврат прежнего браузера через системные настройки отключает маршрутизатор.

Синтетические ID из unit-тестов не предназначены для реального подключения.

## Соответствие исходников готовой сборке

В архиве `BUILD_INFO.json` фиксирует версию Swift, SDK, версии ОС и параметры
сборки; `SHA256SUMS.txt` содержит хеши файлов архива кроме самого манифеста.
Проверка целостности после распаковки:

```sh
shasum -a 256 -c SHA256SUMS.txt
```

В папке архива есть `REVIEW_BUNDLE.txt`; его можно заново получить из исходников:

```sh
zsh scripts/review-bundle.command
cmp REVIEW_BUNDLE.txt dist/REVIEW_BUNDLE.txt
```

Инструкция позволяет повторить процесс сборки, но **побайтовая воспроизводимость
не гарантируется**. Версии компилятора, SDK, пути, linker UUID и подпись могут
изменить результат. Хеши опубликованных исходников и бинарного файла не являются
криптографическим доказательством того, что второй получен из первых.
Для проверки кода без доверия к готовому исполняемому файлу соберите свою копию.

## Зависимости

Во время работы используются Foundation, AppKit и системный NSWorkspace.
Во время сборки — zsh, xcrun/swiftc/lipo, codesign и стандартные инструменты macOS.
Для тестов URL нужен Swift. Сторонних библиотек и субмодулей Git нет.
Отдельный установщик использует системный Bash 3.2, curl, shasum, ditto, codesign,
xattr и другие встроенные утилиты macOS; ему нужен доступ к GitHub Releases.

## GitHub Actions

В `.github/workflows/checks.yml` описаны независимые задания для Apple Silicon
и Intel на macOS 15. Они выполняют тесты установщика, unit-тесты, сборку, проверку подписи и создание
текстового пакета для аудита. GUI приложения и реальные встречи в CI не запускаются.
Единственный внешний action — официальный `actions/checkout`, закреплённый на
commit версии 4.2.2; токен не сохраняется в Git. Workflow имеет только `contents: read`.
Результат конкретного запуска следует смотреть во вкладке Actions, а не считать
наличие workflow свидетельством успешной проверки.
